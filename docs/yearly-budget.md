# 年度预算与汇率定格（设计草案 v2）

> 状态：**已实现（v1.1.0）**。产品决策于 2026-10-13 确认（见第 13 节），同日完成实现（见第 14 节）。
> 记录日期：2026-10-13。
> v2 修订：始终后台定格（不依赖预算开关）、汇率发布后自动补齐、统计口径可选、逐年金额、双源自动链。

## 1. 目标与场景

- 目标：用户可以**逐年设定预算金额** + 一个结算币种，应用统计当年实际花费的折算合计，展示已花 / 剩余进度。
- 汇率在**录入时定格**：保存记录后按购买日期（可选其它日期）自动获取当时的汇率并存为记录的一部分；**无论预算是否开启都会定格**；之后行情波动不影响历史，预算数字稳定。
- 统计口径可选：包含运费 / 手续费（默认）或只统计盒本体价。
- 价格展示不变：书架、详情、订单等现有界面仍按原币种显示，不做实时换算；折算仅在预算入口可见（「后台默默记录」）。
- 非目标：实时汇率显示、多币种普通统计合并、自动抓取全量行情、超限通知（后续可选）、浮点金额。

场景示例：2026-10-10 在骏河屋花了 12,800 日元（含运费），保存后应用自动按 10-10 的 JPY→CNY 汇率定格；年度预算 ¥6,000.00，首页显示今年已折算 ¥541.44。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 结算币种 | 预算使用的唯一目标币种，设置在预算页（默认取「默认货币」），不随默认货币后续变化而改变 |
| 定格目标币种 | 预算结算币种（已设置时）；否则「默认货币」。此后默认货币变化不影响已定格记录 |
| 定格 | 把「1 原币 = x 结算币」的汇率快照写入记录，含实际采用的汇率日期与来源；此后不再依赖网络 |
| 待定格 | 记录已保存、目标日期汇率尚未发布或网络失败；应用启动 / 回到前台自动重试，超过 3 天仍无数据 → 提示手动填写 |
| 归年日期 | 记录计入哪一个自然年：收藏 = 购买日期，缺失时用所属订单的下单日期；费用 = 所属订单的下单日期。缺失 → 未计入（缺日期） |
| 未计入 | 无法折算的记录分类：缺价格 / 缺日期 / 未定格 / 定格币种不符；绝不猜测、不补 0 |

定格与归年相互独立：定格日期默认等于归年日期，允许单独选择（例如按信用卡结算日），两者不一致时不影响归年。

## 3. 数据模型

### 3.1 Room v5（`owned_copy`、`expense` 各加 4 个 nullable 列）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `fxRateScaled` | INTEGER? | 定格汇率 × 10^9（1 单位本行币种 = fxRateScaled / 10^9 结算币）；null = 未定格 |
| `fxDate` | TEXT? | 实际采用的汇率日期（ISO-8601） |
| `fxToCurrency` | TEXT? | 定格时的目标币种（3 位大写） |
| `fxSource` | TEXT? | `currency-api` / `frankfurter` / `manual` |

- `MIGRATION_4_5` 只 `ALTER TABLE ADD COLUMN`，不改动任何旧列；schema 导出到 `app/schemas/`，`MigrationTest` 增加 v4→v5 数据保留用例。
- 折算金额**不落库**：由定格汇率与当前金额实时算出，价格后续修正自动保持一致。
- 币种为空 / 金额为空的行不产生定格；行币种 == 目标币种时不需要定格，直接计入。

### 3.2 领域层

- `OwnedCopy`、`Expense` 增加同名字段；`Mappers` 双向映射补齐。
- 新增 `domain/model/Fx.kt`（或并入 `Money.kt`）：
  - `FxRate` 值对象：`rateScaled: Long`（×10^9）+ 解析 / 格式化（展示形如 `1 JPY = 0.0423 CNY`）。
  - `convert(amountMinor, fromDecimals, rateScaled, toDecimals): Long`：BigInteger 定点运算、四舍五入（half-up）、溢出抛消息键。
- 新增 `domain/cost/BudgetEngine.kt`（纯函数）：
  - 输入：行列表（金额、币种、归年日期、定格字段）+ 目标币种 + 年份 + 口径（含费用 / 仅本体价）。
  - 输出：已折算合计、按年（或月）分布、未计入分类清单（`NOT_PRICED` / `NO_DATE` / `NOT_FROZEN` / `STALE_TARGET`）。
  - 只产生消息键（`domain/text/Message.kt`），不引用 Android。

### 3.3 DataStore 设置

| key | 类型 | 默认 |
| --- | --- | --- |
| `budget_enabled` | Boolean | false |
| `budget_currency` | String | 首次开启时取当前「默认货币」；不随默认货币变化 |
| `budget_yearly_amounts` | JSON `map<年份, Long>` | 空（每年单独设定金额，可预填未来年份） |
| `budget_include_fees` | Boolean | true（含运费 / 手续费） |

沿用「按需展示」哲学：预算不开启时首页无任何预算元素（但定格仍照常后台进行）。

### 3.4 备份 v2 可选字段扩展（沿用既有策略，不升版本号）

- `BackupCopy`、`BackupExpense` 增加 `fxRateScaled` / `fxDate` / `fxToCurrency` / `fxSource`（全部可选，缺省 = 未定格）。
- `BackupSettings` 增加可选 `budget`（enabled / currency / yearlyAmounts 逐年金额 / includeFees）。
- 校验：`fxRateScaled > 0`；`fxToCurrency` 三位大写；`fxDate` 可解析；四个字段要么全空、要么全套齐全；年份在合理区间、金额 ≥ 0。
- 旧备份恢复后全部显示「未定格」，不静默按当前汇率补历史；新备份在旧版本应用读取时被忽略（既有 `ignoreUnknownKeys` 行为）。

## 4. 汇率来源（已实测，2026-10-13）

| 来源 | 端点示例 | 覆盖 | 历史范围 | 实测行为 |
| --- | --- | --- | --- | --- |
| fawazahmed0/currency-api（jsDelivr / pages.dev 双镜像） | `https://cdn.jsdelivr.net/npm/@fawazahmed0/currency-api@2026-10-10/v1/currencies/jpy.min.json` | ~200 币种，含 TWD | 约 2024-03-02 起 | 单币种全表约 6 KB（JPY）；按日期出包，含周末；当天数据尚未发布（试 `@2026-10-13` 不存在，`latest` 有滞后） |
| frankfurter.dev（ECB 官方参考汇率） | `https://api.frankfurter.dev/v1/2026-10-09?base=JPY&symbols=CNY` | ECB 币种，**无 TWD** | 1999 起 | 周末 / 节假日自动回退到最近交易日，响应 `date` 字段给出实际日期；`symbols` 不支持时报 `not found` |
| 手动填写 | — | 全部 | 全部 | 自动获取失败 / 币种不支持 / 断网时的最终兜底 |

选择策略：

1. 目标日期 ≥ 2024-03-02 → 先 currency-api（覆盖广、含 TWD、CDN 对国内网络相对友好）；失败或目标日尚未发布 → 尝试 frankfurter（若两币种均被 ECB 支持）；再失败 → 保持待定格。
2. 目标日期 < 2024-03-02 → 先 frankfurter（历史到 1999）；不支持该币种 → 标记需手动填写（不会随重试出现）。
3. 同一次批量补全内，同一（日期, 原币）只请求一次（内存去重）。
4. 目标日期汇率尚未发布（通常是当天）→ 保持待定格，按 7.5 自动重试；**不使用邻近日期冒充**。
5. 超过 3 天仍取不到数据 → 停止自动重试并提示手动填写（阈值 3 天为实现默认，可调）。
6. 每条定格都记录 `fxSource` 与实际 `fxDate`，方便审计与重定格。

请求规则：

- 保存 / 编辑外币记录后自动请求定格（无需先开启预算）；升级前的旧记录不会被自动批量请求，使用「补全历史」显式触发。
- 请求只含币种对与日期，不带任何用户数据。
- 超时沿用现有习惯（连接 15s / 请求 30s），单次触发失败不循环重试；重试时机见 7.5。
- 解析用 `JsonPrimitive.content` + BigDecimal，不经过 Double，不引入浮点。

## 5. 折算规则

- 方向固定：`fxRateScaled` 表示「1 单位本行币种 = x 单位目标币」。
- 换算公式（定点，BigInteger）：
  `convertedMinor = roundHalfUp(amountMinor × fxRateScaled × 10^toDecimals / (10^fromDecimals × 10^9))`
- 小数位数取 `Money.decimals()`（JPY=0、CNY=2…）。
- 合计使用 `Money.add`；单行 / 合计溢出均拒绝并提示，不静默截断。
- 例：12,800 JPY，汇率 0.042299852（`42299852` × 10^-9）→ ¥541.44（54,144 分）。

## 6. 预算口径

- 口径可配置（设置项，默认「含费用」）：
  - 含费用（默认）：每盒 `priceMinor`（已记录价格）+ 每笔费用 `amountMinor`（运费 / 手续费全算，与实际支出同口径）；
  - 仅本体价：只统计每盒 `priceMinor`，费用不计入也不列入未计入。
- 不计入并分类展示：
  - 缺价格（`priceMinor == null`）；
  - 缺日期（无购买日期且无订单日期）；
  - 未定格（外币且有金额 / 日期，但没有汇率快照）；
  - 定格币种不符（`fxToCurrency` ≠ 当前目标币种，需重定格）。
- 同一份记录只计一次：盒的价格按盒计，费用按费用计；与分摊结果无关。
- 删除 / 移动记录沿用现有行为：删订单级联删费用（预算自动减少）、收藏盒保留（orderId 置空、价格仍计）。预算页的「未计入」数量会随这些操作变化，属于预期。

## 7. 界面与交互

### 7.1 设置

设置 → 收藏 增加「年度预算」入口：

- 开关（默认关）、结算币种（默认 = 默认货币）、统计口径（含运费 / 手续费（默认）或仅本体价）。
- 逐年金额：为选中年份填写任意金额（`Money.parse` 同规则）；当前年突出显示，可预填未来年份，往年可补设。
- 数据源说明与免责声明：参考汇率来自公开接口，可能与银行卡实际结算有差异；可在记录上手动修正。
- 「补全历史」：列出可定格但未定格的记录数，一键批量定格（逐条状态与失败可见）。
- 变更结算币种：旧定格标记「币种不符」，提供「按原日期重新定格到新币种」。预算首次开启时若已有定格的目标币种 ≠ 结算币种，走同一流程。

### 7.2 首页

预算开启后显示一张年度预算卡：本年已折算 / 本年预算金额、进度、未计入计数；点击进入预算详情。金额未设置时只显示已花合计并提示设定。不开启则完全不显示。

### 7.3 预算详情页

- 年份切换（默认当年；按年展示该年金额与已折算合计，往年可补设金额；月分布可选）。
- 未计入分类清单：缺价格 / 缺日期 / 未定格 / 币种不符，每条可跳转到对应编辑页或触发重新定格、手动填写。

### 7.4 录入表单（新增 / 编辑收藏、订单、费用）

当行币种 ≠ 定格目标币种时，显示一行紧凑的「汇率定格」：

- 状态：已定格（`1 JPY = 0.0423 CNY · 2026-10-10 · currency-api`）/ 待定格 / 需手动填写。
- 操作：选择日期（默认购买日 / 订单日，可改）、重新获取、手动填写（>0，最多 9 位小数）、清除。
- 保存后自动尝试定格：后台执行、不阻塞保存、失败不影响保存（沿用 `CoverWarmer` 的「保存后预热」模式与失败语义）。
- 修改记录币种时清除定格并提示重新获取（防止方向错位）。

### 7.5 触发时机

| 时机 | 行为 |
| --- | --- |
| 新增 / 编辑收藏（有日期、外币） | 后台定格（无论预算是否开启） |
| 新增 / 编辑订单（订单日期变化） | 只定格该订单中尚未定格的记录；已定格的不自动改 |
| 新增 / 编辑费用 | 按订单日期后台定格 |
| 收藏被加入 / 移出订单 | 加入后若满足条件则后台定格；移出不改已定格值 |
| 应用启动 / 回到前台 | 静默重试「待定格」记录（限量、去重）；超 3 天仍无数据则转为「需手动填写」 |
| 打开预算页 | 触发一次重试并展示各状态 |
| 用户点「补全历史」 | 按（日期, 币种）去重批量定格旧记录 |

## 8. 边界情形

- **当天汇率尚未发布**：保持「待定格」，发布后自动重试补齐；不使用邻近日期替代。超过 3 天仍无数据 → 提示手动填写。
- **未来日期**（误填）：取不到数据 → 保持未定格，提示检查日期。
- **结算币种变更**：旧定格保留但计入「币种不符」，不静默按错币种统计。
- **手动修正**：任何定格都可手动改写或清除；手动值 `fxSource = manual`；手动值不参与自动重试覆盖（除非用户主动重新获取）。
- **历史数据 / 升级**：旧记录初始为未定格（同币种行直接计入）；升级后不会被自动批量请求，通过「补全历史」或逐条补录。
- **备份恢复**：定格字段随备份往返；旧备份恢复后为未定格；恢复期间不联网。
- **离线**：所有定格尝试失败即静默保留待定格状态，不影响任何本地功能。

## 9. 隐私与网络

- 新增网络端点仅两个公开汇率接口（见第 4 节），全部免 key。

- 保存 / 编辑外币记录后会自动请求（无需先开启预算）；升级前的旧记录只有用户点「补全历史」时才请求。失败不影响本地功能。

## 13. 已确认决策（2026-10-13）

1. **始终后台定格**：保存 / 编辑外币记录后自动定格，不依赖预算开关；升级前的旧记录用「补全历史」显式补全。
2. **等发布后自动定格**：当天汇率未发布时保持待定格，发布后自动重试补齐；不使用邻近日期冒充；超过 3 天仍不可得或来源不支持时提示手动填写。
3. **统计口径可选**：设置项选择「含运费 / 手续费」（默认）或「仅本体价」。
4. **逐年预算金额**：每年单独设定金额，可预填未来年份、回看往年。
5. **双源自动链**：currency-api 优先、frankfurter 兜底、手动最终兜底；每条记录标注来源与实际汇率日期。
6. **定格目标币种**：预算结算币种（已设置）否则默认货币；已定格记录不受后续默认货币变化影响。

- `FxFreezer`：保存后后台请求（返回 `Job` 仅供测试等待）；应用启动 / 回前台只重试最近 3 天（旧记录不会自动批量请求）；「补全历史」显式批量；手动定格 / 清除；修改币种自动清除快照。
- 显式「重新获取」可刷新同目标币种的已有快照；自动来源记录的购买日期、批次日期依据变化时清除并重新定格；慢请求写回前校验日期依据，避免并发编辑后旧汇率覆盖新记录。手动定格不会因日期编辑而被自动覆盖。
- DataStore 预算设置（开关 / 结算币种 / 逐年金额 / 统计口径）；备份 v2 增加可选 `settings.budget` 与记录级定格字段，旧备份保持本机设置并显示未定格。
- UI：设置 → 年度预算（含补全历史与数据源说明）、首页预算卡、预算详情（年份切换、四类未计入、重新获取 / 重新定格 / 手动填写 / 去补填）、收藏编辑页定格行；订单、费用保存与订单日期编辑后同样触发定格。
- 测试：`FxTest`、`BudgetEngineTest`、`FxRateSourceTest`（本地假服务器）、`FxFreezerTest`、`MigrationTest`（v4→v5）、`BackupTest`（定格与预算往返、旧备份）、`BudgetUiTest`；全量 JVM / Robolectric 回归通过。
